# Med Rive

Med Rive is a Flutter prototype for a mobile Medcare / Wellness app. The project showcases application architecture, integration with a mock backend, and interactive Rive animations.

The planned user flow includes first-run onboarding, interactive breathing-session choices, and a personalized summary. Mock data will provide the user's profile, and Rive animations will respond to the user's choices. This is a technical demo.

The project uses Flutter 3.50.0, managed with [FVM](https://fvm.app/).

## Tools and libraries

### State management and dependency injection

- [BLoC](https://bloclibrary.dev/) for application state management
- [get_it](https://pub.dev/packages/get_it) and `injectable` for dependency injection

### Navigation

- [go_router](https://pub.dev/packages/go_router) with type-safe routes generated by `go_router_builder`

### Animations

- [Rive](https://pub.dev/packages/rive) for interactive animations

## Application structure

```text
lib/
├── common/
│   ├── data/
│   │   └── onboarding/
│   │       ├── data_sources/
│   │       ├── dtos/
│   │       ├── models/
│   │       ├── use_cases/
│   │       └── onboarding_repository.dart
│   ├── error_handling/
│   ├── injection/
│   ├── l10n/
│   └── navigation/
│       └── routes/
├── features/
│   ├── breath_session/
│   │   └── pages/
│   └── onboarding/
│       └── pages/
├── main.dart
└── med_rive_app.dart
```

`features/` groups presentation code by feature. Feature-specific `state/`, `views/`, `widgets/`, and `utils/` folders can be added as needed. Shared data capabilities live under `common/data/<capability>/`, organized into data sources, DTOs, application models, use cases, and a repository.

Data sources handle transport or storage formats. Repositories map DTOs to application models so that use cases, Blocs, and UI code do not depend on JSON or backend response shapes.

The intended data flow is:

```text
UI → Bloc → use case → repository → data source
```
